# Purpose

This document defines the standard development workflow for the ERGS Dynamics Website.

Following a consistent workflow ensures that every feature is planned, implemented, verified, documented, and maintained using the same engineering process.

---

# Workflow Philosophy

A consistent engineering process produces consistent software.

Development speed is important, but maintainability, reliability, and long-term quality always have higher priority.

---

# Standard Development Lifecycle

Every feature must follow this sequence:

1. Plan
2. Create Backup
3. Implement
4. Verify
5. Refine
6. Update Documentation
7. Final Review
8. Complete

No step should be skipped without a documented engineering reason.

---

# Rule 1 — Plan Before Coding

Understand the problem before writing code.

Define the objective, expected behaviour, affected files, and possible future impact before implementation begins.

---

# Rule 2 — Backup Before Changes

Create a backup before making structural or significant modifications.

Backups provide a safe recovery point during development.

---

# Rule 3 — One Feature at a Time

Complete one feature before starting another.

Avoid mixing unrelated work within the same implementation session.
